# Pacta web UI

How the UI is put together, and how to extend it without touching the contract.

## Layers

| Layer | Where | Rule |
|---|---|---|
| Category registry | `src/catalog/` | Everything product-specific: units, attributes, milestone templates, verifier label, wording. |
| Campaign metadata | `src/lib/metadata/` | Off-chain details behind `metadata_uri`, versioned (`despensa.campaign/v1`), validated with zod. Never throws. |
| Rules (pure) | `src/lib/actions.ts`, `wizard.ts`, `reputation.ts`, `format.ts` | No React, no SDK. Mirror the contract's guards. Unit-tested. |
| Contract and chain reads | `src/lib/despensa.ts`, `events.ts`, `contract-spec.ts` | The only code that talks to Stellar. The contract interface is bundled (see below). |
| Data hooks | `src/lib/hooks.ts` | Cached reads (`useQuery`), invalidated by prefix after a transaction (`invalidateCampaign`). |
| Components | `src/components/` | Receive a `CategoryDef`. Never contain a product word. |
| Pages | `src/app/` | Compose the above. |

**Never re-derive a rule in a component.** What a person can do is `nextActions(campaign, holding, role, now, disputeWindow, { bond, category, deliveries })`. Components render the `Action[]` it returns, and `argsFor(action, id, me, values)` builds the contract call.

## Adding a product category

Example: coffee sold by the kilo.

1. Create `src/catalog/coffee.ts`:

   ```ts
   import type { CategoryDef } from "./types";

   export const coffee: CategoryDef = {
     id: "coffee",
     group: "bebidas",
     label: "Café de altura",
     icon: "Coffee",                // a name in catalog/icons.ts, or an emoji
     accent: "coffee",              // kept for compatibility; categories are no longer colored
     unit: { singular: "kilo", plural: "kilos", short: "kg", step: 1, maxPerOrder: 20 },
     deliveryMode: "pickup",
     perishable: false,
     attributes: [
       { key: "variedad", label: "Variedad", type: "text", placeholder: "Typica, Caturra", showOnCard: true },
       { key: "tostado", label: "Tostado", type: "select", required: true, showOnCard: true,
         options: [{ value: "medio", label: "Medio" }, { value: "oscuro", label: "Oscuro" }] },
     ],
     milestoneTemplates: [
       { title: "Cosecha y despulpado", suggestedPct: 15, evidenceHint: "Fotos de la cosecha y del lote." },
     ],
     verifierLabel: "Asociación de caficultores",
     defaults: { saleDays: 14, deliveryDays: 60, minUnits: 20, maxUnits: 200, unitPrice: "9.00" },
     priceDisplay: { decimals: 2 },
     copy: { tagline: "El café de la próxima cosecha, al precio de hoy.", producerNoun: "finca" },
   };
   ```

2. Add one line to `CATEGORIES` in `src/catalog/index.ts`.
3. If the icon is new, add it to `src/catalog/icons.ts`.
4. Open `/dev/catalog` (development only) and check the card, the attributes, the milestone note and the button labels.

That's all. The marketplace chips, the campaign page, the create wizard and the voucher wording pick it up. Categories are told apart by icon and name, not color, so there is no color to add.

**Roadmap categories:** set `comingSoon: true`. They appear in the marketplace with a "pronto" note and are disabled in the wizard ("Muy pronto").

**Wording keys** (`copy`): `tagline`, `voucherNoun` (vale / reserva), `producerNoun`, `deliveryVerb`, `confirmVerb`, `productionStage`. Defaults live in `catalog/generic.ts`.

## Contract interface

`src/lib/contract-spec.ts` holds the deployed contract's interface, generated by `scripts/sync-contract-spec.mjs`. Bundling it saves every fresh page load from downloading the contract code (35 KB, two RPC round trips) before its first read.

- After every redeploy or upgrade: `npm run spec:sync`.
- `npm run spec:check` exits 1 when the bundled spec no longer matches the deployed contract.
- `contract-spec.test.ts` fails if a method the app calls, or one of its argument names, or a field of `Campaign` / `CampaignInput`, is missing from the spec.

## Campaign metadata

`metadata_uri` holds one of:

- `data:application/json;base64,…`: the default. Stored on-chain, so keep it small: the wizard warns above 1 KB and refuses above 4 KB. Photos go in as links, not files.
- `https://…` or `ipfs://<CID>`: fetched and validated. IPFS publishing is a stub.
- Anything else: a legacy plain-text description, shown with the `generic` category.

A document that fails to load or validate renders with the fallback and a "detalles no disponibles" note. Schema: `src/lib/metadata/schema.ts`.

## Live hand-off

The delivery happens on two phones. `usePolling` (in `lib/hooks.ts`) refreshes only what the other side can change, only while the tab is visible:

- buyer (campaign page, Mis vales): the holding, every 6 to 8 s while they hold vouchers in a live campaign, so "¿Recibiste…?" appears as soon as the producer registers the delivery;
- producer (delivery page): the buyer's holding, every 5 s after "Entregué", until it is confirmed, disputed or settled.

The header shows a count on **Mis vales** when deliveries wait for confirmation or refunds wait to be claimed.

## Verifiers

The wizard offers known verifiers as one-tap choices (`lib/verifiers.ts`): on testnet, the deployment's verifier account, labeled as a test account. Add real ones with `NEXT_PUBLIC_KNOWN_VERIFIERS`, a JSON array of `{ address, name, note?, categories? }`. "Otra persona o institución" accepts an address, but the contract only takes verifiers on its allowlist: the wizard reads `is_verifier` (`useVerifierAllowed`) and blocks the step with a clear message when the address isn't allowed. The admin adds one with `set_verifier` (see the project README). The list in `lib/verifiers.ts` is only labels for the wizard; it doesn't allow anyone.

## Dispute window

Each campaign carries its own `dispute_window`, fixed when it was created. `nextActions` and every countdown read it from the campaign. `config.dispute_window` is only what new campaigns will get.

## Screens: rules

- **One primary action per screen.** `ActionList` makes the first enabled action primary; everything else is `btn-secondary` or `btn-ghost`.
- **Progressive disclosure.** Explanations of terms go in a `Hint`; long lists of figures go in a `<details>`. Fees, risks, time limits and irreversible consequences never go only in a `Hint`: they stay in the page or the confirm step.
- **Hierarchy by type and spacing first.** Cards are for things you can open or act on (campaign cards, voucher rows, the buy panel, role panels). Sections are a heading and space, not a box.
- **States.** Every read has a skeleton, an error `Notice` with "Reintentar", and an `EmptyState`. Every transaction goes through `TxSteps`.
- **Read-only mode** is explained once, in the banner (`READ_ONLY_ID`); disabled buttons point to it with `aria-describedby` (`readOnlyProps`).

### Hint (tooltip)

`Hint` opens on mouse hover, keyboard focus and tap; Esc, a tap outside, scroll or resize close it. The button is 24×24 px with an `aria-label` ("Qué es: Custodia"), and the text is linked with `aria-describedby`, so screen readers read it with the button. It positions itself inside the viewport. `Term` wraps a glossary word with a `Hint`.

### Money movement

`TxSteps` shows Preparando → Firmando → Confirmando en Stellar, then one of three `MoneyStatus` states:

| State | When | Shown as |
|---|---|---|
| Completado | Confirmed in a ledger | success icon + "Completado" and the explorer link |
| Pendiente | The network accepted it but didn't confirm it within 45 s (`waitForTx`) | info clock + "Pendiente", "No la repitas" |
| Falló | Rejected before or on the network | error icon + "Falló", the reason and "No se movió tu dinero" |

## Color

Tokens live in `src/app/globals.css`, with a dark-mode set. Components use the token names only (`bg-surface`, `text-ink-2`, `text-warning`, `bg-danger-soft`…), never raw palette classes or hex values. `.theme-light` forces the light set on a subtree (the printed poster, the voucher QR).

**Base hue: green, 152°** (`#1E6B47`, the logo). Green reads as money, growth and "safe to go"; kept deep and slightly desaturated, it reads as stable rather than playful, which is what a product holding other people's money should feel like. It also ties to the producers: milk, eggs, vegetables.

**Accent: amber, 40°** (from the video's coins and stars, and the aguayo textile). It is the warm, local counterweight to the green. Used only for small highlights (rating stars, streak flame, the "something to do" dot); never for body text.

**Neutrals: warm paper.** The neutral scale is tinted toward the amber (hue ≈ 40°, low chroma), so pages feel like paper and market stalls, not a bank terminal.

**Semantic colors** each come with an icon and a word, so color is never the only signal:

| Role | Light | Dark | Icon | Use |
|---|---|---|---|---|
| Success | `#1E6B47` on `#E4F0E9` | `#5CC490` on `#1B3226` | check | Money released, delivery confirmed, goal met |
| Warning | `#8A5300` on `#FBEFD9` | `#E8AD52` on `#3A2B14` | triangle | Deadlines, "no se puede deshacer", things waiting on you |
| Error | `#B4352A` on `#FBE8E5` | `#F08072` on `#3E1D19` | alert / x | Failed transactions, defaults, invalid input |
| Info | `#24609E` on `#E2ECF8` | `#74ABE9` on `#172A40` | info / clock | Pending money, "en entrega", neutral notices |

Info blue is the one hue outside the brand pair: a cool, calm color for "in progress" that can't be mistaken for success (green) or a problem (amber, red).

### Type and space

Fraunces for headings (`h-page`, `h-section`), Geist for everything else; `h-sub` is a semibold body-size heading. Body text is `text-base`, secondary text `text-sm`; `text-xs` is only for pills and chart labels. Radii: `rounded-full` (pills, chips, icon buttons), `rounded-xl` (controls, notices, inner boxes), `rounded-2xl` (cards, dialogs, media). Pages separate sections with `space-y-10`.

## Wording

Spanish (Bolivia), `es-BO` number and date formats: decimal comma, period for thousands. Dollars are written one way, `$us 1,00` (`formatMoney`), with bolivianos as `≈ Bs 12,00`. Prefer *vale*, *custodia*, *aval*, *verificador*, *dólares digitales* over crypto terms, and attach a `<Term>` on first use. The product is **Pacta**; its line is *No es una promesa. Es un pacto.*

Unit names change gender between categories (*litros*, *canastas*), so never put an adjective or article that must agree with them next to a quantity. Write "entregas pendientes por 2 litros", not "2 litros entregadas".

## Tests

`npm test` (vitest). Covered: the bundled contract spec against every call the app makes, action rules for every status × role, contract argument names, dashboard badges, the events reader (paging, decoding), metadata adapters, wizard validation and conversion (including the DESIGN.md money example), reputation tiers, money and number formatting, and which actions are flagged irreversible.

## Known limits

- **Testnet latency:** a single RPC request to the public testnet takes anywhere from 0.2 to 4 seconds. Pages fire their reads in parallel, so a fresh page waits for its slowest request (the delivery page makes 3).
- **Read-only without Pollar:** without `NEXT_PUBLIC_POLLAR_PUBLISHABLE_KEY` nothing can be signed. Pages show a banner, and actions are disabled with the reason.
- **Event retention:** pending deliveries and disputes come from contract events, which RPC keeps for about 7 days. Older ones fall back to a "type the buyer's address" action.
- **Identical units:** the contract treats all units in a campaign as the same, so for apartments use one campaign per apartment type.
